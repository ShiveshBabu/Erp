● CONNECTED TO PRODUCTION BACKEND — NOT FULLY PRODUCTION-READY YET
This is now talking to a real Node/Fastify API backed by real PostgreSQL. What's genuinely real:
• Passwords are hashed server-side with argon2id — never stored or compared in the browser.
• Sessions are server-side (Postgres-backed) with an HTTP-only cookie — there is no auth token sitting in localStorage to steal.
• Every permission check is re-verified on the server for every request — this page's buttons hide for convenience only; the backend rejects unauthorized calls regardless.
• Invoice/payment/transfer/production operations run inside real database transactions with concurrency-safe stock updates.
Still not complete: no automated backup pipeline (see backend/README.md for the documented strategy), no email-based password reset, no CSRF token on top of the session cookie, and some simpler screens (e.g. editing an existing warehouse/supplier/BOM) aren't wired to the backend yet.
⚠ LOCAL / DEMO MODE — NOT PRODUCTION READY
This application runs entirely in your browser with no server. That means:
• Passwords are hashed with a simple non-cryptographic function for basic obfuscation only — this is not production-grade security (no salting, no bcrypt/argon2, no server-side verification).
• There is no real session management, no HTTP-only cookies, no login throttling, and no server to enforce permissions — a technically sophisticated user could bypass checks by editing the page.
• All data lives in this browser's local storage only. It is not backed up automatically, not shared between devices, and can be lost if storage is cleared.
• Multiple people using this at once are not really "multi-user" — there's no concurrency control or transaction locking across sessions.
To become production-ready this needs: a real backend server, a real database, server-side authentication with secure sessions, API-level authorization checks, transaction/concurrency handling, and an automated backup strategy — none of which a browser-only app can provide.
